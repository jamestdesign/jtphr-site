# photo-grade v1 開發誌(2026-05-08 ~ 2026-05-12)

<p class="font-bold text-red-400 mb-2">🔴 一句話定義</p>
<div class="text-sm text-gray-300">

2026-05-08 到 2026-05-12 五天時間,把人像評分 SKILL 從 17 條規則訓練到 v3 + 6 條防幻覺紅線 + Stage A/B 分跑 production pipeline + LR catalog v4 metadata schema 拍板,完成 671 張門司港訓練集 + 1280 張 4 趟 backlog production 跑完的完整開發歷程。

## 1. 四天時間軸

### 📅 2026-05-08(週四)— 訓練日

**主題**:門司港 671 張 SKILL 訓練 + AutoTone 機制定版

**早班**:
- 訓練 Green 軸(17 規則 + 19 視覺錨點)
- 跑 230 張 Green production(92 P)

**晚班**:
- User audit 14 張 1★ + 30+ 周邊 → 浮現 13 條 calibration → SKILL v2 升級(30 條完整規則)

**技術突破**:
- EXIF orientation 修預覽 bug(113 ARW + 18 HEIC)
- R+Y 慷慨原則 v2 跑 379 張(212 P)
- catalog label 中文化(紅 / 黃 / 綠 / 紫)

**驗證**:
- VLM vs user QC 165 張改動率 27.5%(4→3 拉回 42 + 2→3 升 28 + Pick 過給 -18)

---

### 📅 2026-05-09(週五)— Catalog 機制日

**主題**:Robert_AT_P preset + 全歸零 + XMP tag-name 踩坑

- 跑 Robert_AT_P 130 張紅 + Pick → 發現 HSL / Color Grading 殘留
- 學到「重跑前先問是否全歸零」feedback

**LR Develop preset 設計(暫存,等進階階段實作)**:三段式 =
- **AutoTone**(per-photo 自動)
- **Adaptive Mask**(per-photo AI mask,可選)
- **氛圍 Preset**(全組統一)

**XMP 寫入踩坑紀錄**:
- ColorGrade 反用 SplitToning 舊 tag names
- `crs:Saturation` 在 `-o` sidecar 模式會消失
- PickLabel non-portable
- NFC / NFD 路徑歸一化

---

### 📅 2026-05-10(週六)— 整合日

**主題**:Evoto round-trip v3 + 出片 pipeline + Backlog SOP 寫死

**晨間發現**:
- Evoto 不接 LR AI Remove(生成式 cache 不還原)
- → SOP 順序對調:LR 純參數 → Evoto 質感肌 → 回 LR 做 AI Remove

**v3 升級**:
- Evoto 修完不再回 `<scene>/Evotofu/`
- 直接到 `_export/<scene_top>/`(出片軌)
- 完整 KB 寫成獨立 markdown

**Orientation 大坑修補**:
- 不要抄 ARW orientation flag 給 Evoto JPG
- 要讀 JPG 實際 dims 設 "AB"

**1280 張 backlog v1 完成**:
- Sonnet 跑 4 趟共 ~2 小時 / 595K tokens
- 結果 794 / 1280 = 62% Pick

**1057 場景幻覺事件**(本期最重大教訓):
- Sonnet 在 1057(133 張)幻覺率 70-80%
- 空沙發 → 搞怪 / 酒瓶 → 風景 / 熊本熊合照 → 木雕
- User 花 90 分鐘 calibration → 制定 6 條防幻覺紅線

**SOP 寫死**:
- Backlog 旅遊 trip 必走 5 階段
- GPS+VLM 雙來源命名
- HHMM-only 不算交付

---

### 📅 2026-05-11(週日)— 一條龍 production 日

**主題**:Stage A+B 1280 張全跑完 + 1112 拆 14 子場景

**凌晨**:用 Opus 4.7 重跑 backlog Stage A 標籤(包含 1057),拆兩階段執行,完整覆蓋 1280 / 1280

**上午**:
- Stage B 評分 + 1112 場景拆 14 子場景(動線 A~O)
- 10 張廢片黑標(2 張非行程 + 8 張糊片 / 截圖)

**工具產出**:
- `_master_stage_b_rating.csv`
- `1112_subscene_mapping.json`
- `_apply_rating_to_xmp.sh`(dry-run 98.2% 配對率)

**決策修正**:
- James 確認「Excire 不再當 gate」(因 face / people 兩道閘都漏)
- 維持全 Opus 三步分跑

**角色定位**:James(總指揮)+ Robin(秘書 / 管理者)+ Robert(執行)三方分工確認

---

### 📅 2026-05-12(週一)— 寫入端定版日(v4 拍板)

**主題**:v4 LR Catalog Metadata Schema 拍板

**背景**:
- 實測發現 LR Classic 13+ 對 `altTextAccessibility` / `extDescrAccessibility` 兩個 IPTC 2017 新欄位,SQL 直寫 column 不會進 search index、UI 不顯示

**拍板**:
- VLM 結果改用 SQL 一定吃的欄位
- 關鍵字承載 `objective_description`(用 `+` 切)
- 註解承載機器 tag + 雙方對話日誌(`|` 數標輪次)
- 評等 / 旗標 / 色標 維持 v3

**對話日誌規則**:
- Robert 初寫 → James 加註(單 `|`)→ Robert 回應(雙 `||`)→ append-only,永不覆蓋

**Smart Collection**:
- 可從註解的 `[需補tag]` / `[需複查]` / ` || ` 篩出狀態子集
- 取代之前的 XMP round-trip 思路

## 2. Pipeline 演進史

整個 SKILL + 工作流的版本演化:

| 版本 | 日期 | 主要變更 | 取代原因 |
|---|---|---|---|
| **v0.5** Excire-as-gate | 2026-05-07 | Excire 預先分類 + VLM 細評 | face / people 兩道閘漏報率高(後腦勺 / 側臉 / 逆光剪影) |
| **v1** SKILL 17 規則 | 2026-05-08 早 | Green 軸 17 規則 + 19 視覺錨點;Excire 信號當「先驗」不當 gate | 規則 10「大組擇優+餘降 2★」太嚴,被 user 校為「沒大瑕疵=3★」 |
| **v2** SKILL 30 規則 | 2026-05-08 晚 | 13 條 calibration 修正:雷同處理、唯一性 6 維度、抽象 mood / 街頭紀念、1★ 門檻精煉 | Sonnet 大批量幻覺率高(1057 場景 70-80%) |
| **v3** SKILL + 防幻覺紅線 | 2026-05-10 | 6 條紅線:`objective_description` 必填、Label 由主體唯一決定、同場景同 label、`conf<0.7` flag、Opus only、拆兩階段 | 評分軸定版,寫入端尚待設計 |
| **Production 確定版** | 2026-05-08 確認 | 場景分組 → 標籤 → 評分 三步分跑全 Opus,~$48/天(600 張) | 為 Stage A+B 分跑做準備 |
| **Stage A+B 分跑** | 2026-05-11 | 拆 Label-only pass(含 `objective_description`)+ Rating pass — 不准合併 | 已被 v4 LR Catalog Metadata Schema 接續(寫入端定版) |
| **v4** LR Catalog Metadata Schema | 2026-05-12 | VLM 結果 → LR catalog 的**欄位分工拍板**:關鍵字承載 `objective_description`(用 `+` 切);註解承載機器 tag + 雙方對話日誌(`|` 數標輪次);替代文字 / 延伸描述**暫不用** | **當前 production(寫入端)** |

### 定版決策(2026-05-08)— 全程 Opus 換精準

User 要求精準度優先,省時間避免反覆校正。
- 成本:Opus ~$48/天 vs Sonnet ~$9/天
- 但 Sonnet 在 1057 場景證實大批量幻覺率 70-80%,不適合 production
- Sonnet 只能用於 dev / sample audit
