## 這次的模式（meta-thinking）
- 搬機匯出時要分清「可直接搬」與「機器綁定需重建」兩類：skills/記憶/腳本可搬；MCP OAuth token、API 金鑰、TCC/FDA 權限、plugin 快取屬機器綁定，只能在新機重設 → README 一定要列出「沒帶進來、需手動重建」清單，避免對方以為包內就是全部
- 排程搬機不能只搬 plist：plist 只是觸發器，真正的工作在它呼叫的腳本；要遞迴追依賴（wrapper.sh → worker.py → .claude/scripts/ → KB repo 內 sync-kb.sh），把腳本本體一起打包才可運作
- 面對「這個依賴我可以不要嗎」的問題 → 先查該依賴實際負責哪一段、拿掉後什麼會壞什麼還能動，用「保留 vs 移除」的取捨表回覆，而不是直接照做或直接拒絕
- 交付給「另一個 LLM 執行」的包，README 要寫成可執行步驟（改路徑→放檔→load→驗證）＋安裝後必補清單，而非給人看的敘述
- launchctl bootout 只停到下次登入；要跨重開機保持停用得把 plist 改 .disabled — 停排程時要主動點出這個差別
