產出自動分場景 export-auto-move

LR 匯出的成品 JPG，依母檔所在的 day／場景，自動分天分場景鏡射到 _export。完全不碰 catalog（A 方案，中繼資料已烤進 JPG）。

做什麼

LR 匯出成品 JPG→<trip>/to_export/→export-auto-move→_export/<dayN>/<場景>/
  • 用檔名（去副檔名）當鑰匙，掃 trip 各 day 的 主/次/<場景>/ 母檔，建「stem → (day, 場景)」對照表。
  • 把 to_export/ 的每張成品 JPG，鏡射搬到母檔對應的 _export/<day 資料夾>/<場景>/。
  • 結構：① 分天（每個 dayN 一夾）　② 主/次合併（OPPO 與第二台放同一場景夾）。

怎麼用

# 1) 先 dry-run（只報告，不搬）— 看每個 day/場景幾張，對不對
export-auto-move "<trip 根目錄>"

# 2) 確認無誤 → 實際搬
export-auto-move "<trip 根目錄>" --go

# 可選：自訂來源/輸出夾（預設 <trip>/to_export 與 <trip>/_export）
export-auto-move "<trip>" --to_export /path/in --export /path/out --go
# 可選：--ext jpg → 只搬指定副檔名（例：跳過 to_evoto 的 .tif 送洗中間檔）
export-auto-move "<trip>" --to_export "<trip>/to_evoto" --ext jpg

別名 to_export 亦可

腳本 tools/export_auto_move.py

自動兼容結構

  • 場景平鋪＋_次（2026-07-01 新）：day 底下場景平鋪，次相機 = 主場景名＋_次（如 08_…_次/）→ 依母檔所在場景鏡射，_次 也照樣落 _export/…/<場景>_次/。
  • 舊 主/次 子夾（向後相容）：<trip>/<dayN>/主(次)/<場景>/ 仍照吃。
  • 多日 vs 單日：多日 → _export/<dayN>/<場景>/（分天）；單日（場景直接在 trip 下）→ _export/<場景>/ 攤平。四種組合自動偵測。
  • Evoto round-trip：-EVT / -EVTO 成品尾綴自動 strip，對得上母檔；to_evoto 的 .tif 送洗中間檔用 --ext jpg 跳過。

前提 & 規則

  • LR Export 檔名選「原始檔名」 → 成品 stem 才對得上母檔（例 RKLU8425.jpg ↔ 母檔 RKLU8425.DNG）。
  • 尾綴會先 strip 再比對：-2 / -Edit / -Enhanced / -NR / -HDR / -Pano / -EVT / -EVTO…；但母檔本身真實的 _01 尾會保留不誤刪。
  • 對不上（找不到母檔）的檔會列清單、留在 to_export/，不亂搬 → 你檢查檔名。
  • 同名衝突（一個 stem 對到多場景）會在報告裡標 ⚠️（實務上 trip 內檔名唯一，通常 0 衝突）。

對照範例（德國 5天4夜實測）

to_export 檔名處理落點
RKLU8425.jpg直接對上 DNGday2 / 08 瑪麗安橋
IMG…114215-2.jpg去 -2day2 / 04 宮殿洞窟
IMG_0496-Edit.jpg去 -Editday1 / 04 車上點心
IMG_7958-Enhanced-NR.jpg去 -Enhanced-NRday1 / 08 慕尼黑

母檔 1032 張、stem 全唯一、0 場景衝突。

💡 鐵則：一定先 dry-run 看「鏡射預覽（每 day/場景張數）」對不對，再加 --go。搬檔是移動（同碟秒級），對不上的絕不亂丟。
