① 一句話總結

② 名詞表

縮寫全名意思 / 用途
MOV影片本體原始 .MOV/.mov/.mp4，_MOV/<scene>/IMG_XXXX.MOV 永遠不切
STILL抽幀靜畫ffmpeg 從 MOV 抽出的 JPG，_STILL/<scene>/IMG_XXXX_sNN_tXX.XX.jpg
NGNo Good失誤段（對焦/穿幫）— 只標註不切原檔，劇本生成跳過
KPKeep剪輯保留段（轉場/慢動作素材）— 抽 1 幀代表進劇本縮圖區
HLHigh Light（舊名 HP）精彩瞬間 — 切獨立 clip 直接壓縮出片。HL ⊆ KP，自動納入劇本候選
KFKey Frame從 STILL P=1 反推回 MOV 的時間點（自動產生，寫進 MOV keyword）
-EVTEvoto 後綴Evoto 出來的 JPG 必加 -EVT 區別於 LR Develop 出的 JPG
💡 小貼士：KF 是自動產生的（VLM 評完 STILL P=1 後反推），不是手動標的。你只標 NG / KP / HL，KF 自動回填到 MOV keyword。

③ 三標記重定義（2026-05-17 v2 拍板）

標記意義處理
HL High Light — 精彩瞬間，可獨立切出直接壓縮出片 ffmpeg 切 <clip>_hlNN.mp4 進 _export/<scene>/ + 自動納入劇本 KP 候選
KP Keep — 剪輯時要保留的段（交叉剪/慢動作/故事連續性） 段中間秒數 ffmpeg 抽 1 幀代表 → _KP_preview/<clip>_kpNN_tXX.XX.jpg
NG No Good — 失誤段（對焦/穿幫/拍壞） 只標註不切原檔。劇本生成跳過該段

HL ⊆ KP 規則

⚠️ 不需重複標

標 | HL:9.0-10.5 → 同時視為：① 獨立切片出片 + ② 劇本 KP 候選

標 | KP:0.0-5.0 → 純劇本素材參考（不獨立出片）

HL 自帶 KP 屬性，不要重複寫 | HL:X-Y | KP:X-Y。同一片段只切一次。

④ MOV rating 0-5★ = 影片類型

💡 重點：STILL rating 1-5★ 是「品質」（構圖/曝光/瞬間），MOV rating 0-5★ 是「類型」 — 同欄不同意義，LR 按檔案類型自然區分。
★類型出片規則
0★生活紀錄（預設不評就是）即使 P=1 也不直接出片 — KF + KP 仍可進劇本
1★專題報導（課程整片）整片保留 + NG 註記切除版剪輯出片
2★活動攝影（演唱會/說明會）直接剪在一起放雲端保存（不精修）
3★保留（待定義二級類型）進剪輯流程
4★精彩瞬間P=1 → 直接壓縮出片 + 二次剪輯
5★史詩級保留（婚禮/作品集/首映）P=1 → 直接壓縮出片 + 二次剪輯

分水嶺：直接出片 vs 剪輯出片 在 4★ ✓

⑤ MOV colorLabel = VLM 主體分類

跟 rating 是獨立兩個維度：

colorLabel意思（VLM 看主體判定）
R 紅人像五官明顯多（臉清楚）
Y 黃看不到五官的人像（背影/側臉/動作）
G 綠風景
P 紫食物 / 藝術品 / 物件
B 藍（暫未啟用）

判定來源：9-V-a 多數投票 — 該 MOV 抽出的所有 STILL（不挑 P=1）→ 對每張 STILL 的 label 多數決 → MOV label

範例：永漢 IMG_6232.MOV 抽 18 張 STILL，14 張 Y + 4 張 G → MOV label = Y（14/18 投票）

💡 為什麼跟 rating 不衝突：rating = 內容類型（這是哪種影片？），colorLabel = 視覺主體（主畫面是什麼？）。例：永漢 IMG_6232 = 3★ Y（生活紀錄 + 人像背影）。

⑥ Caption 格式 C 混合版

Robert 寫的 turn 0（自動）

[label:<R/Y/G/P>] [confidence:<X.XX> 投票 <得票>/<總票>]
元件例用途
label:YYMOV 主視覺（R/Y/G/P 之一）
confidence:0.780.78 浮點程式可排序/filter（<0.7 flag 等 audit）
投票 14/18比例人類一眼看懂（14 票對 18 張）

你 audit 後 turn N（append，用 | 分隔）

[label:Y] [confidence:0.93 投票 14/15] | HL:9.0-10.5  揮桿頂點精彩 | KP:0.0-5.0  開場跑桿可作轉場 | NG:7.0-8.5  對焦失誤

KF 獨立到 keyword 欄

LR keyword 列表（IMG_6230.MOV）:
  KF:01.00
  KF:08.00
  KF:13.00
💡 為什麼 KF 不放 caption：避免重複（caption 已被 NG/KP/HL 佔），keyword 欄 LR 搜尋打 KF 就抓到。zero-pad 2 位小數確保排序正確（KF:06.00 < KF:12.00）。

⑦ STILL 抽幀 + 命名規格

抽幀 ffmpeg 命令（雙保險）

ffmpeg -nostdin -loglevel info \
  -i _MOV/<scene>/IMG_XXXX.MOV \
  -vf "select='isnan(prev_selected_t)+gte(t-prev_selected_t\,3)+gt(scene\,0.1)',showinfo" \
  -vsync vfr -q:v 2 \
  /tmp/_extract_IMG_XXXX_%04d.jpg
  • gte(t-prev_selected_t,3) = 每 3 秒至少抓 1 張（fps=0.33 保底）
  • gt(scene,0.1) = 動作變化大（球桿位置/鏡頭切換）額外抓 1 張（scene-detect 加碼）
  • showinfo 把 pts_time 寫到 stderr，parse 後當 timestamp
  • 永漢 sample 結果：72→33 砍 54%，關鍵幀（揮桿頂點/球車 transition）沒漏

命名格式

<MOV basename>_s<NN>_t<秒.毫秒>.jpg

範例：
IMG_6230_s01_t00.00.jpg     ← MOV 起始幀
IMG_6230_s02_t00.02.jpg     ← scene-detect 抓的
IMG_6230_s03_t03.02.jpg     ← fps=0.33 保底
IMG_6230_s07_t15.02.jpg     ← 15.02 秒
  • s<NN> = scene order（從 1 開始，zero-pad 2 digits）
  • t<XX.XX> = MOV 時間點（秒.毫秒，固定 2 位小數）
  • 打開 LR 一邊看 MOV 一邊看 STILL，檔名直接對應時間點最方便

手動 STILL（James 自己截圖）

命名格式：IMG_<src>-<N>_t<秒.秒>.jpg
範例：IMG_6221-1_t05.20.jpg  ← 源 IMG_6221 / 第 1 張手動 / 5.20 秒
放置：_STILL/<scene>/（跟自動 STILL 同層）
💡 2026-05-17 B 案拍板：手動 STILL 不走 LR stack，直接搬到 _STILL/<場景>/，9-P-c extension 腳本會處理 catalog folder pointer 更新。

JPG metadata 內嵌（2026-06-02 拍板，雙寫鐵則）

所有 STILL（自動抽 + 手動截圖）的 metadata 全部塞進 JPG 本身的 EXIF/IPTC/XMP 區段，不出 .xmp sidecar、不出 .txt 副檔。

為什麼內嵌

  • 檔案 self-contained：搬到任何地方都帶著資訊
  • 跨 catalog 攜帶：LR Classic / LR 雲端 / Apple Photos / iCloud / Bridge 全認
  • 沒有 sidecar 走失風險：.xmp 可能跟主檔分離，內嵌不會
  • 對齊既有「metadata 雙寫鐵則」（2026-05-31 拍板）：catalog SQL + JPG 內嵌 XMP 雙寫，catalog 崩才能 import 從 XMP 讀回

寫入欄位（exiftool 命令範例）

exiftool \
  -overwrite_original \
  -codedcharacterset=utf8 \
  -DateTimeOriginal="2026:05:15 11:46:28" \
  -Source="IMG_6230.MOV @ t=03.02" \
  -Keywords="KP_R" -Keywords="Star5" -Keywords="<scene>" \
  -Caption-Abstract="[label:Y] [confidence:1.00 投票 8/8]" \
  -XMP-dc:Description="[label:Y] [confidence:1.00 投票 8/8]" \
  -XMP-lr:hierarchicalSubject="影片來源|IMG_6230" \
  IMG_6230_s03_t03.02.jpg

# 注意：
# • 沒有 -o 旗標 = 直接寫進原 JPG 內嵌，不產 sidecar
# • -codedcharacterset=utf8 = 強制 IPTC Caption-Abstract 用 UTF-8
#   （IPTC 預設 Latin-1，不加這條中文 caption 會亂碼，2026-06-02 九州 trip 踩過）
# • XMP-dc:Description 跟 IPTC Caption-Abstract 同步雙寫
#   （XMP 原生 UTF-8，更穩；IPTC 給舊版工具相容）

欄位 → LR 顯示對照

欄位內容LR 哪裡看
DateTimeOriginal原 MOV 時間 + 抽禎秒偏移時間軸排序
Source<MOV 檔名> @ t=<秒.秒>Metadata 面板
KeywordsKP 分類 / Star / 場景關鍵字面板
Caption-Abstract機器 tag + | + 對話日誌（caption 格式 C）註解面板
Rating留空，James 進 LR 後評星級
XMP:Label (Pick)留空，VLM/James 決定Pick 旗標 / Color Label
XMP-lr:hierarchicalSubject影片來源|<MOV 檔名>階層關鍵字
🚨 鐵則
  • ❌ 不出 .xmp sidecar（除非 LR Develop 設定需要，那是另一回事）
  • ❌ 不出 .txt / .json 副檔
  • ✅ 全部走 JPG 內嵌（exiftool 不加 -o 旗標）
  • ✅ catalog SQL 同步寫（雙寫鐵則）

⑧ 路徑結構（v2 平層）

<trip>/
├── 1146 開場球洞_自拍/                ← 照片場景（ARW + Evotofu/）
├── 1206 高點觀景/
├── 1300 高點揮桿_核心/
├── ...
├── _MOV/<scene>/<clip>.MOV           ← 原檔母片（永遠不切）
├── _STILL/<scene>/...                 ← STILL 抽幀（自動 + 手動同層）
├── _KP_preview/<clip>_kpNN_tXX.XX.jpg ← KP 段抽 1 幀代表
├── _to_evoto/                         ← TIFF 暫存（Evoto 用）
├── _to_export/                        ← LR Develop 出 JPG 暫存
└── _export/<scene>/                   ← 出片區（平層，不再下鑽）
    ├── <photo>.jpg                    ← 照片出片
    ├── <photo>-EVT.jpg                ← Evoto 精修
    ├── <clip>_hlNN.mp4                ← HL 切片
    ├── <clip>_4star.mp4               ← 4★/5★ 整段
    └── memoirs/<edited>.mp4            ← 剪輯完成版
💡 為什麼平層：James 要在 LR 內1 個資料夾看完 photo + video，不必下鑽子層。所以 _export/<scene>/ 內 photo / EVT / hl / 4star 全平層。

⑨ MP4 編碼規格（LR 預覽相容）

ffmpeg -i <src.MOV> \
  -vf "scale=-2:1080,format=yuv420p" \
  -c:v libx264 -pix_fmt yuv420p \
  -crf 20 -preset slow \
  -c:a aac -b:a 192k \
  -movflags +faststart \
  <dst.mp4>
參數原因
scale=-2:10801080p，雲端/手機觀看標準
H.264 (AVC)LR Classic 預覽相容（HEVC 在 LR 顯示灰畫面，known bug）— 檔案比 H.265 大 ~30% 但相容稅必付
format=yuv420p強制 8-bit 色深（原 MOV 10-bit 直編 QuickTime/LR 都不解）
CRF 20視覺接近無損
preset slow出片不在乎時間，壓得小
+faststart邊載邊播
AAC 192k通用音訊 codec
🔥 踩坑紀錄（2026-05-17）
  • v1 預設 H.265 10-bit → QuickTime 不解 video，LR 灰畫面
  • v2 改 H.265 8-bit + -tag:v hvc1 → QuickTime 通了，LR 還是灰畫面
  • v3 改 H.264（本版）→ 全部過

結論：LR Classic 預覽 HEVC 不穩，出片以 LR 為主就 H.264 fix。

⑩ Pick=-1 (Reject) → 物理刪除釋出空間

規則：LR 內把 MOV 標 Pick=-1（Reject）→ Robert explicit cleanup script 跑後物理刪除 MOV 釋出 NAS 空間。

處理範圍

  • ✅ 刪 MOV 本體（_MOV/<scene>/<clip>.MOV）
  • ❌ 不刪 STILL（已有 KF 視為「保留那 STILL 不剪輯這段」）

安全機制（B 案）

  1. 先搬到 _TRASH/<scene>/<clip>.MOV（quarantine）
  2. 7 天後 cron 真刪（或下次 cleanup 跑時看到 >7 天才真刪）
  3. 誤標 -1 → 7 天內可從 _TRASH/ 救回

觸發時機

explicit 跑 cleanup_rejects.py 才執行（不在 9-V-a 自動觸發，嚇人）
