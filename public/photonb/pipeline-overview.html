🔁 共用核心邏輯(綠色節點)

共用核心 S1–S8：場景命名 / VLM 標籤 / VLM 評分 / catalog 寫入 / AutoTone / LR review — 照片 + 影片都走同一套，最後一起上雲。
🛠️ 這段前端流程 ＝ 工具 素材歸場景（scene_build）（pipeline 第一步）：倒卡素材一口氣時區校正→分天分場景→VLM 評分/色標/關鍵字→寫 XMP→歸檔，並鋪好 LR 目錄與 FCP 資料庫工作檔。功能說明統一在該工具頁維護。

為什麼共用很關鍵：

  • 一份 catalog 管 photo + STILL —— LR 不必區分，評分軸一樣
  • 一份 VLM 評 photo + STILL —— 不必為影片另寫 prompt
  • 一份 v4 schema 寫入 —— 關鍵字 + 對話日誌格式統一
  • STILL 帶 source_video + timestamp，跟原片對應
  • 共用 GPS + VLM 場景命名 —— 影片跟照片同場景自動配對

📊 兩條流的並排比較

📷 照片端(成熟)

  • 流程：評分 → 分類 → 場景 → catalog → 出片（9P-a~c）
  • 評分：人像 4 軸法（紅黃綠紫）
  • 後製：Evoto round-trip（Red+P 精修）
  • 色調：HarborDiary + 色調庫
  • 輸出：JPG → _export/<場景>/ → 上雲
  • 實作狀態：✅ 評分 / catalog / 出片都 production

🎬 影片端（V2.1）

  • 攻略：影片剪輯攻略書 V2.1（撿片為核心）
  • 抽幀：智慧抽幀 scene-detect 為主・減量（評場景用途）
  • 評分：共用照片 VLM（STILL = 影片抽出的幀）
  • 撿片：James FCPX 標 KP(i/o+keyword) / HL(4★5★) / NG
  • 出圖：Robert 批次 KP 抽 4K + HL 短片段 + 1★ 去 NG 拼接
  • 輸出：H.264 1080p → _export/<場景>/ → 上雲
  • 實作狀態：📐 schema 定稿，fcpxml_extract.py 待寫（9V-c）

🎯 LR catalog 是兩條流的「交會點」

整套架構最關鍵的設計判斷:把影片抽出來的 STILL 放進**同一個 LR catalog 跟照片一起評分**(共用節點 Step 6/7)。

為什麼這麼設計:

  1. 不必為影片另建 catalog / 另寫評分系統 / 另設 UI
  2. James 在 LR review 時,photo 跟 STILL 同視覺體驗(同 4 軸 / 同色標 / 同 Pick)
  3. v4 metadata schema 統一(關鍵字 + 註解 + 評等 + 旗標 + 色標)
  4. Smart Collection 跨 photo + STILL 都能用
  5. 未來如要對 STILL 做精修(crop / 印刷)→ 跟 photo 同樣的 develop preset 工作流

差異點:

  • 影片 clip 本身也進 catalog(LR 支援影片 import),但 LR 對影片只能 clip-level 評分(色標 / Pick / caption),沒 frame-level marker
  • 所以 frame-level 操作（挑 keeper 那一禎、框精彩段）由 James 在 FCPX 做（9V-a），Robert 從 XML 抽 4K / 切片
  • STILL 帶 source_video + timestamp 兩個資訊，跟原片建立對應
