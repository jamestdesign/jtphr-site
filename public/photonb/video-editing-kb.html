④ 智慧抽幀 · S3

抽幀的目的

抽幀不是為了找 keeper（keeper 你 FCPX 自己挑），而是：

  • 讓 Robert 跟你看得懂這段影片在拍什麼（場景用途評分）
  • 抓住敏感動作 / 轉場那幾個關鍵瞬間
  • 靜態、環境沒大變化的區段 → 不抽（省得一堆雷同廢圖）

抽幀邏輯：scene-detect 為主

ffmpeg -nostdin -loglevel info \
  -i _MOV/<scene>/IMG_XXXX.MOV \
  -vf "select='isnan(prev_selected_t)+gte(t-prev_selected_t\,10)+gt(scene\,0.4)',showinfo" \
  -vsync vfr -q:v 2 \
  /tmp/_extract_IMG_XXXX_%04d.jpg
參數值意義
時間保底 gte(t-prev,N)10 秒靜態長鏡頭最少每 10 秒留 1 張「能看懂」
scene 門檻 gt(scene,X)0.4只在明顯動作 / 轉場（球桿揮動、鏡頭切換、人物進出）才加抽，小晃動不抽
首幀 isnan(prev)留永遠抽 t=0 起始幀（代表這段開頭）
💡 兩個參數怎麼調：scene 門檻 0.4 是起點 — 如果發現轉場漏抓就降到 0.3，如果還是太多雷同圖就升到 0.5。時間保底 10 秒對「靜態訪談 / 風景定鏡」夠用；動態運動類可降回 6 秒。每個 trip 第一支先試跑一張看抽幾張，再定參數。
⚠️ 抽幀量預期

一支約 70 張原始幀的影片，這組參數大約抽 15 張上下。純靜態時段可能只剩開頭 1 張 —— 那正是你要的（那種時段本來就沒 keeper）。每個 trip 第一支先試跑看抽幾張再微調。

評分重點：從「品質」改成「場景用途」

抽出來的 STILL 進 LR 後，Robert 的 VLM 評分主要回答一個問題：

這段影片是幹嘛用的？→ 對應 MOV rating 類型（見 §5）+ colorLabel 主體 + 一句 objective_description。

不再花力氣替每張 STILL 評 keeper 星等（那是你 FCPX 撿片的事）。VLM 仍遵守 防幻覺 6 條紅線（objective_description 必填、Opus only、拆兩階段、confidence<0.7 flag…）。

⑤ 評分系統（用途 + 主體）· S4–S5

MOV rating 0–5★ = 影片「類型 / 用途」

💡 重點：STILL rating 是「品質」，MOV rating 是「類型」 — 同一欄、不同意義，LR 按檔案類型自然區分。這就是「這個場景幹嘛用的」答案。
★類型出片規則
0★生活紀錄（預設不評就是）即使 P=1 也不直接出片 — KF + KP 仍可進劇本
1★長篇發表（去 NG）（導覽 / 介紹 / 課程）i/o 框整段 + Delete 標壞鏡頭 → Robert 去 NG 拼接成一支完整檔（見下方）
2★活動攝影（演唱會 / 說明會）直接剪在一起放雲端保存（不精修）
3★保留（待定義二級類型）進剪輯流程
4★精彩瞬間P=1 → 直接壓縮出片 + 二次剪輯
5★史詩級保留（婚禮 / 作品集 / 首映）P=1 → 直接壓縮出片 + 二次剪輯

分水嶺：直接出片 vs 剪輯出片 在 4★。

1★ 長篇發表「去 NG 拼接」

情境：導覽 / 介紹這類長片，整段大致要留，但中間夾雜很多壞鏡頭（吃螺絲 / 穿幫 / 對焦跑掉）。

你做：① I/O 框「要的整段」② 段內壞鏡頭選起來按 Delete（= Reject 紅標）。

Robert 做：抓出你框的整段 → 照 Reject 位置把壞段挖掉 → 把剩下的好段（第 1 段 + 第 2 段 + 第 3 段…）接成一支完整影片、一個檔（hard cut，預設不加轉場）。

# 取 keep 段 = i/o 範圍 − Reject 段，逐段裁切後 concat 成一支
ffmpeg -i <clip>.MOV -vf \
  "select='between(t,<k1s>,<k1e>)+between(t,<k2s>,<k2e>)+...',setpts=N/FRAME_RATE/TB" \
  -af "aselect='between(t,<k1s>,<k1e>)+...',asetpts=N/SR/TB" \
  -c:v libx264 -crf 20 -preset slow -c:a aac -b:a 192k -movflags +faststart \
  _export/<scene>/<clip>_clean.mp4
💡 NG 處理分兩種：只有 1★ 長篇發表會把 NG 切掉再拼接；其他類型（0★/2★…）NG 一律「只標不切」，你自己剪輯時再決定。

MOV colorLabel = VLM 主體分類（跟 rating 獨立）

label意思（VLM 看主體判定）
R人像五官明顯（臉清楚）
Y看不到五官的人像（背影 / 側臉 / 動作）
G風景
P食物 / 藝術品 / 物件

判定來源：該 MOV 抽出的所有 STILL → 對每張 label 多數決 → MOV label。
例：永漢 IMG_6232 抽 18 張，14 Y + 4 G → MOV = 3★ Y（生活紀錄 + 人像背影）。

⑥ 三標記 + KF 自動回填

標記意義誰標處理
HL 精彩瞬間（= rating 4★/5★）— 動態照片用短片段 James（FCPX：I/O 範圍 + keyword 為準；Favorite F 只是綠色視覺輔助；clip 給 4★/5★） Robert 切短片段 <clip>_hlNN.mp4（1080p H.264 faststart）→ 網路相簿動態照片
KP 你親手挑的單禎好畫面 + 主體分類 James（FCPX：I/O 同一禎 + keyword KP_R/Y/G/P） Robert 抽 4K 單禎 JPG，R/Y/G/P 寫進 XMP（LR 色標 + 關鍵字）→ _export/<scene>/
NG 失誤段（對焦 / 穿幫 / 拍壞） James（FCPX：keyword，或 1★ 用 Delete=Reject） 短素材 只標不切；1★ 長篇發表 切掉再拼接（見 §5）
KF 關鍵幀時間點 自動（不用標） 從 STILL 評分反推回 MOV，寫進 MOV keyword KF:XX.XX
⚠️ HL 與 KP 不必重複標

HL 是「精彩片段」（出短片），KP 是「好單禎」（出靜照）—— 兩件不同的事。HL 段裡若剛好也有想當靜照的那一禎，再單獨點 KP 即可，不用整段重標。

💡 KF 不用你標：你只標 NG / KP / HL。KF 是 LR 那邊 STILL 評完後 Robert 自動反推回 MOV keyword 的（搜尋 KF 就抓到時間點）。

⑦ Caption / Keyword 格式

Robert 寫的 turn 0（自動，進 LR caption）

[label:<R/Y/G/P>] [confidence:<X.XX> 投票 <得票>/<總票>]

你 audit / 標註後 append（用 | 分隔；若改在 FCPX 標則由 XML 帶）

[label:Y] [confidence:0.93 投票 14/15] | HL:9.0-10.5 揮桿頂點 | KP:3.20 開場好神情 | NG:7.0-8.5 對焦失誤

KF 獨立到 keyword 欄（LR 搜尋 KF 抓得到）

IMG_6230.MOV keyword:  KF:03.02   KF:15.02
💡 zero-pad：時間一律 2 位小數（KF:06.00 排在 KF:12.00 前），caption 永遠 append 不覆寫（它同時是對話日誌容器）。

⑧⁰ 旅遊影片匯入fcpx（Robert 先建 Library）· 工具 trip_fcpx_build

🛠️ 工具：旅遊影片匯入fcpx（trip_fcpx_build）· 已實證 比利時day2-4 / 德國day1-6（421 clips）

把整趟 MOV_<day> 一次匯進 FCP，自動分好 event 與場景關鍵字，James 開 Library 直接撿片，不用一夾一夾手動拖。

  • event = 每天（主／次各自獨立 event，不混）
  • 每個場景 = 一個 keyword collection（clip 自動掛該場景名當關鍵字 → 撿片時用關鍵字分類找片）
  • 影片 leave-in-place（media-rep 指原檔，MOV_ 當唯一原檔家，不複製、不佔空間）
  • 新平鋪 _次 與舊主/次子夾兩種結構都吃
trip_fcpx_build.py "<trip>"/MOV_*/ --library "<….fcpbundle>" -o 匯入FCP.fcpxml
# → 產 fcpxml；再 FCP「File ▸ Import ▸ XML」或雙擊匯入（也可走 SpliceKit import_fcpxml）
💡 跟 §8 的關係：這步取代 §8「一次性設定」裡「手動匯入 _MOV」那一動 —— 用工具產 fcpxml 一次匯完（已自動 Leave-in-place + 場景關鍵字）。匯完就照 §8 綁 KP/HL 快捷鍵開撿。配套出圖端 = fcpxmld-export（§9）。

⑧ FCPX 撿片操作 · 9V-a（標記）+ 9V-b（Export XML）

一次性設定（每個新 Library 做一次）

✅ 開工前
  1. 匯入 _MOV/ → 取消勾 Copy to library（選 Leave files in place，影片太肥不複製）
  2. HDR 對話框 → Keep as Standard (SDR)
  3. Cmd+K 開 Keyword Editor → 綁 NG(Ctrl+1) + KP_R/KP_Y/KP_G/KP_P(Ctrl+2~5)。HL 不用 keyword（用 Favorite F + 星等 4★/5★）

💡 KP 一鍵搞定：I/O 框到那一禎 → 按 KP_R/Y/G/P keyword（依主體：臉清楚 R / 背影 Y / 風景 G / 物件 P）。一個動作同時標「位置 + 分類」，畫質無損（Robert 從原片抽 4K）。比打 marker 省 —— marker 要「位置 + 分類」兩個註記。

交件：Export XML 三步

  1. 側邊欄選中 Event（不是 Project / 不是 Library 最上層）
  2. File → Export XML… → 版本選最新（1.10+）
  3. 命名 <trip>_<日期>.fcpxml → 把 .fcpxml + _MOV/ 路徑丟給 Robert
💡 一次 export 驅動全部：KP keyword + HL（Favorite + 4★/5★）+ NG keyword 全在同一個 XML 裡，Robert 一支腳本全處理。你只交一次 XML，不用分 KP / HL 兩次給。（這是 §13 效率建議的核心。）

維運 ①：搬 NAS 後 reconnect

⚠️ FCPX 記絕對路徑

Library 記的是絕對路徑，從 X10 Pro 搬到 NAS 後第一次開會跳「missing files」。但有智能 reconnect，一次指認資料夾就全好：

  1. FCPX 關閉 → 整個 trip 資料夾原樣搬 NAS（_MOV/、LR catalog、FCP Library 一起搬）
  2. 從 NAS 開 Library.fcpbundle → 跳 missing files → 點 Locate All…
  3. 選 NAS 上的 _MOV/ → FCPX 自動把所有 clip 重連
💡 關鍵是「_MOV/ 跟 Library 的相對結構不變」。搬完別改 _MOV/ 名字，否則要逐個重連很痛苦。

維運 ②：Library 暫存清理（瘦身 30–70%）

✅ 不會刪你的成果

選中 Library → File → Delete Generated Library Files… → 勾 Render / Optimized / Proxy → Delete。只清「衍生暫存」（可重建），Keyword / Favorite / Marker / Timeline 100% 保留。

時機：出完片要搬 NAS 前 / Library > 50GB / 季度封存時。

⑨ Robert 批次出圖（讀 XML 自動跑）· 9V-c · 工具 fcpxmld-export

🛠️ 工具：fcpxmld-export（已定型・實證 day1/2/4 零錯誤）

你在 FCPX 撿完片，Export 一個 .fcpxmld 交給我，一條指令全自動出圖：

fcpxmld-export <trip>/_MOV/xxx.fcpxmld

工具讀 .fcpxmld 內的 keyword / star，自動切 HL 片段 + 抽 KP 單禎，分場景輸出並寫好 LR 可讀標註。命名 / 分場景 / 轉檔 / 標註全自動，你不用手動做任何一步。

🔒 輸出版面（鎖死・不要每次不一樣） 
<trip>/_preview_mov_KP/<場景>/   ← KP 單禎 JPG
<trip>/_preview_mov_HL/<場景>/   ← HL 片段 mp4

<場景> = day 場景夾名（如 day1 趕赴札幌帝王蟹之旅/1801 札幌薄野蟹本家品蟹）。命名一眼看出是「mov 導出的預覽檔」。

⚠️ 素材若被 FCP 託管進 .fcpbundle，工具一律改抓 day 場景夾的原檔，輸出才會落對場景（不會套進 bundle 深層路徑）。

AKP → 原生解析度單禎抽圖 + 分類寫進 XMPRobert

讀 XML 裡 KP_R/Y/G/P keyword 的時間點（I/O 單禎）→ ffmpeg 從原片抽該禎原生解析度 JPG（-q:v 1），再把分類寫進 XMP：

# 抽單禎（HLG 來源先 tonemap 轉 SDR，否則畫面會灰）
ffmpeg -ss <t> -i <clip> [-vf <HLG→SDR>] -frames:v 1 -q:v 1 \
  _preview_mov_KP/<場景>/<clip>_KP<色>_t<秒.秒>.jpg

# R/Y/G/P 寫進 XMP，LR import 直接讀到色標 + 關鍵字 + 來源時碼
exiftool -XMP:Label=<Red/Yellow/Green/Purple> \
  -Keywords=KP_<色> -Keywords=<場景> \
  -Source="<來源檔> @ t=<秒>s" <out.jpg>

→ 你 import LR 直接看到色標（紅臉 / 黃背影 / 綠風景 / 紫物件）+ 關鍵字 + 來源時碼，不用再標一次。

BHL（Star4★/5★）→ 動態照片短片段Robert

讀 XML 裡 rating 4★/5★ 的範圍（認定以 keyword + i/o 為準，Favorite 綠標只是視覺輔助）→ ffmpeg 切短片段（H.264 1080p faststart）→ 放網路相簿當動態照片觀賞：

# 切片段（精準到幀重編碼，不用 -c copy 避免關鍵幀對不齊）
# HLG 來源（iPhone IMG_*.MOV）先 tonemap 轉 SDR，手機 VID*.mp4 原樣
ffmpeg -ss <start> -t <dur> -i <clip> \
  -vf "[HLG→SDR,]scale=-2:1080,format=yuv420p" -c:v libx264 -crf 20 -preset medium \
  -c:a aac -b:a 192k -movflags +faststart \
  _preview_mov_HL/<場景>/<clip>_Star<4/5>_<NN>.mp4

段邊界 = 你 I/O 框的範圍（你框多長出多長）。Star3 = 只記不切。

CStar1（長篇發表・去 NG）→ 移除 Reject 拼成一支Robert

你 I/O 框整段 + 段內壞鏡頭按 Delete(Reject) → 工具讀 Reject 範圍，挖掉壞段、把剩下好段 concat 成一支完整長片。

# 成品也落 _preview_mov_HL，但檔名標 Star1（一眼看出是去 NG 長片）
_preview_mov_HL/<場景>/<clip>_Star1_<NN>.mp4

屬「另外出片」——獨立長片成品，不是 Star4/5 那種當動態照片觀賞的短片段。⚠️ 此 concat 功能尚在待補，規格已定。

DNG → 只記錄不切Robert

短素材的 NG 段寫進 metadata 供劇本 / 剪輯跳過，原檔不動（只有 Star1 長篇會真的去 NG 拼接）。

💡 命名全自動：檔名（場景 / clip / 等級 / 時間）全由腳本依 XML 生成，你不用手動命名、不用手動搬檔。出完直接進 _export/<scene>/ 等你剪輯。

⑪ 編碼規格

出片 MP4（H.264，LR 預覽相容）

ffmpeg -i <src.MOV> -vf "scale=-2:1080,format=yuv420p" \
  -c:v libx264 -pix_fmt yuv420p -crf 20 -preset slow \
  -c:a aac -b:a 192k -movflags +faststart <dst.mp4>
🔥 必踩坑：別用 HEVC

LR Classic 預覽 HEVC（H.265）會顯示灰畫面（known bug）。10-bit 直編 QuickTime / Quick Look 也不解。出片走 H.264 + yuv420p 8-bit，檔案大 ~30% 但相容稅必付。

-frames:v 1 -q:v 2，抽 4K 原寬（之後可 re-frame / 印刷）。

⑬ 效率改善建議（給 James）

你的瓶頸在哪

V2.1 之後，判斷工作全集中在你身上：照片要檢查 + 出片，影片要撿片 + KP + HL + 剪輯。事情變多。下面 6 條照「省你最多動作」排序。

建議 1 ⭐ — KP 維持 i/o 單禎 + keyword（你現行做法已最佳）

2026-06-03 釐清：James 現行 = I/O 同一禎 + keyword KP_R/Y/G/P，畫質完全無損（那只是標時間點，4K 那一禎由 Robert 從原片抽）。一個 keyword 同時做「位置 + 主體分類」，比 marker 省（marker 需位置 + 分類兩個註記）。維持此法，不改 marker。

（先前草稿我寫「改 marker」，是把「i/o + keyword」誤當成「螢幕截圖」才會有畫質疑慮 — 已更正並道歉。）

建議 2 — 一次 Export XML 驅動全部

KP keyword + HL（Favorite + 4★/5★）+ NG 全在 FCPX 一輪標完 → 只 export 一次 XML → Robert 一支腳本全跑（KP 抽 4K 圖 + 寫 XMP / HL 切短片段 / NG 記錄）。不要分「KP 給一次、HL 給一次」，減少你的交付動作。

建議 3 — 工具不要來回跳

影片端「人的判斷」全集中在 FCPX 一次做完，照片端全集中在 LR。在一個工具裡把該做的判斷一次做滿，再交給腳本，比邊看邊跳工具快很多。

建議 4 — Robert 多吃「分類勞動」，你只做「藝術判斷」

場景用途分類、NG 偵測、轉場偵測、主體分類 → 全部 VLM 先做完。你進 FCPX 時，每段已經有標籤告訴你「這是幹嘛的」，你只挑「哪段精彩、哪禎好看」。

建議 5 — 發佈搬檔自動化（沿用照片端）

_to_export → _export/<scene>/ 的搬移由 Robert 腳本一次做（你不用自己搬，除非你想自己搬）。影片切片 / KP 出圖直接落 _export/。

建議 6 — Trip 開工模板腳本

一個 new_trip.sh：自動建好資料夾結構（_MOV/_STILL/_export/...）+ 新建 FCP Library + 提示 keyword 綁定。你開工直接進撿片，不用每次手搭結構。

💡 整體心法：你做的事該只剩「不可外包的藝術判斷」 — 哪段精彩、哪禎好看、怎麼剪。所有「分類、命名、抽圖、切片、轉檔、搬檔、上雲」都是勞動，全歸 Robert 腳本。每多一個你手動做的勞動動作，就是一個可以拿掉的瓶頸。
