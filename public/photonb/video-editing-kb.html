④ 智慧抽幀 V2.1（減量）

V2.1 核心改動

你回饋：「still 抽太多但可用性太少」。所以抽幀目的不再是找 keeper（keeper 你 FCPX 自己挑），而是：

  • 讓 Robert 跟你看得懂這段影片在拍什麼（場景用途評分）
  • 抓住敏感動作 / 轉場那幾個關鍵瞬間
  • 靜態、環境沒大變化的區段 → 不抽（省得一堆雷同廢圖）

抽幀邏輯：scene-detect 為主、時間保底拉長

ffmpeg -nostdin -loglevel info \
  -i _MOV/<scene>/IMG_XXXX.MOV \
  -vf "select='isnan(prev_selected_t)+gte(t-prev_selected_t\,10)+gt(scene\,0.4)',showinfo" \
  -vsync vfr -q:v 2 \
  /tmp/_extract_IMG_XXXX_%04d.jpg
參數V2 舊值V2.1 新值意義
時間保底 gte(t-prev,N)3 秒10 秒靜態長鏡頭最少每 10 秒留 1 張「能看懂」，不再每 3 秒灌
scene 門檻 gt(scene,X)0.10.4只在明顯動作 / 轉場（球桿揮動、鏡頭切換、人物進出）才加抽，小晃動不抽
首幀 isnan(prev)留留永遠抽 t=0 起始幀（代表這段開頭）
💡 兩個參數怎麼調：scene 門檻 0.4 是起點 — 如果發現轉場漏抓就降到 0.3，如果還是太多雷同圖就升到 0.5。時間保底 10 秒對「靜態訪談 / 風景定鏡」夠用；動態運動類可降回 6 秒。每個 trip 第一支先試跑一張看抽幾張，再定參數。
⚠️ 預期效果

永漢實證 V2 是 72→33（砍 54%）。V2.1 參數預估再砍一半，大約 72→15 上下（砍 ~80%）。代價：純靜態時段可能只剩開頭 1 張 — 但那正是你要的（那種時段本來就沒 keeper）。

評分重點：從「品質」改成「場景用途」

抽出來的 STILL 進 LR 後，Robert 的 VLM 評分主要回答一個問題：

這段影片是幹嘛用的？→ 對應 MOV rating 類型（見 §5）+ colorLabel 主體 + 一句 objective_description。

不再花力氣替每張 STILL 評 keeper 星等（那是你 FCPX 撿片的事）。VLM 仍遵守 防幻覺 6 條紅線（objective_description 必填、Opus only、拆兩階段、confidence<0.7 flag…）。

⑤ 評分系統（用途 + 主體 兩個獨立維度）

MOV rating 0–5★ = 影片「類型 / 用途」

💡 重點：STILL rating 是「品質」，MOV rating 是「類型」 — 同一欄、不同意義，LR 按檔案類型自然區分。這就是「這個場景幹嘛用的」答案。
★類型出片規則
0★生活紀錄（預設不評就是）即使 P=1 也不直接出片 — KF + KP 仍可進劇本
1★專題報導（課程整片 / 單一專題）整片保留 + NG 註記切除版剪輯出片
2★活動攝影（演唱會 / 說明會）直接剪在一起放雲端保存（不精修）
3★保留（待定義二級類型）進剪輯流程
4★精彩瞬間P=1 → 直接壓縮出片 + 二次剪輯
5★史詩級保留（婚禮 / 作品集 / 首映）P=1 → 直接壓縮出片 + 二次剪輯

分水嶺：直接出片 vs 剪輯出片 在 4★。

MOV colorLabel = VLM 主體分類（跟 rating 獨立）

label意思（VLM 看主體判定）
R人像五官明顯（臉清楚）
Y看不到五官的人像（背影 / 側臉 / 動作）
G風景
P食物 / 藝術品 / 物件

判定來源：該 MOV 抽出的所有 STILL → 對每張 label 多數決 → MOV label。
例：永漢 IMG_6232 抽 18 張，14 Y + 4 G → MOV = 3★ Y（生活紀錄 + 人像背影）。

⑥ 三標記 + KF 自動回填

標記意義誰標處理
HL 精彩片段範圍（可獨立出片的小片段） James（FCPX keyword） ffmpeg 切 <clip>_hlNN.mp4 + 抽代表圖 → _export/<scene>/
KP 你親手挑的單禎好畫面 James（FCPX marker / 截圖） 抽 4K 單禎 JPG → _export/<scene>/
NG 失誤段（對焦 / 穿幫 / 拍壞） James（FCPX keyword） 只標不切，劇本 / 剪輯跳過
KF 關鍵幀時間點 自動（不用標） 從 STILL 評分反推回 MOV，寫進 MOV keyword KF:XX.XX
⚠️ HL ⊆ KP 規則 — 不要重複標

標 HL 的段，Robert 同時視為：① 獨立切片出片 + ② 劇本 KP 候選。HL 自帶 KP 屬性，不用再對同段補標 KP。同一片段只切一次。

💡 KF 不用你標：你只標 NG / KP / HL。KF 是 LR 那邊 STILL 評完後 Robert 自動反推回 MOV keyword 的（搜尋 KF 就抓到時間點）。

⑦ Caption / Keyword 格式

Robert 寫的 turn 0（自動，進 LR caption）

[label:<R/Y/G/P>] [confidence:<X.XX> 投票 <得票>/<總票>]

你 audit / 標註後 append（用 | 分隔；若改在 FCPX 標則由 XML 帶）

[label:Y] [confidence:0.93 投票 14/15] | HL:9.0-10.5 揮桿頂點 | KP:3.20 開場好神情 | NG:7.0-8.5 對焦失誤

KF 獨立到 keyword 欄（LR 搜尋 KF 抓得到）

IMG_6230.MOV keyword:  KF:03.02   KF:15.02
💡 zero-pad：時間一律 2 位小數（KF:06.00 排在 KF:12.00 前），caption 永遠 append 不覆寫（它同時是對話日誌容器）。

⑧ FCPX 撿片操作精華

一次性設定（每個新 Library 做一次）

✅ 開工前
  1. 匯入 _MOV/ → 取消勾 Copy to library（選 Leave files in place，影片太肥不複製）
  2. HDR 對話框 → Keep as Standard (SDR)
  3. Cmd+K 開 Keyword Editor → 第 1/2/3 格打 HL / KP / NG（自動綁 Ctrl+1/2/3）

撿片快捷鍵（練成肌肉記憶）

快捷鍵動作說明
J K L倒 / 停 / 進多按加速
I / O標入 / 出點選 HL 範圍用
Ctrl+1/2/3套 HL / KP / NG對選取範圍
M加 Marker單一時間點（KP 單禎）
Option+M加 Marker + 命名直接打 KP_R/KP_Y/KP_G Enter
💡 KP 標法二選一：① 範圍 keyword Ctrl+2（一段保留）；② 單禎 M marker（指定那一禎抽圖）。挑「要當靜照出的好畫面」用 marker（精準到那一禎），挑「剪輯要保留的段」用 keyword 範圍。

交件：Export XML 三步

  1. 側邊欄選中 Event（不是 Project / 不是 Library 最上層）
  2. File → Export XML… → 版本選最新（1.10+）
  3. 命名 <trip>_<日期>.fcpxml → 把 .fcpxml + _MOV/ 路徑丟給 Robert
💡 一次 export 驅動全部：KP marker + HL keyword + NG keyword 全在同一個 XML 裡，Robert 一支腳本全處理。你只交一次 XML，不用分 KP / HL 兩次給。（這是 §13 效率建議的核心。）

⑨ Robert 批次出圖（讀 XML 自動跑）

AKP → 4K 單禎抽圖Robert

讀 XML 裡的 KP marker 時間點 → ffmpeg 抽該禎 4K JPG：

ffmpeg -ss <t> -i <clip>.MOV -frames:v 1 -q:v 2 \
  _export/<scene>/<clip>_KP<NN>_t<秒.秒>.jpg

marker 名帶 _R/_Y/_G → 檔名帶等級，方便你排序挑選。

BHL → 切片 mp4 + 代表圖Robert

讀 XML 裡的 HL keyword 範圍 → ffmpeg 切獨立 mp4（H.264 LR 相容）+ 段中抽 1 代表圖：

# 切片（精準到幀重編碼，不用 -c copy 避免關鍵幀對不齊）
ffmpeg -ss <start> -to <end> -i <clip>.MOV \
  -vf "scale=-2:1080,format=yuv420p" -c:v libx264 -crf 20 -preset slow \
  -c:a aac -b:a 192k -movflags +faststart \
  _export/<scene>/<clip>_hl<NN>.mp4
CNG → 只記錄不切Robert

NG 段寫進 metadata 供劇本 / 剪輯跳過，原檔不動。

💡 命名全自動：檔名（場景 / clip / 等級 / 時間）全由腳本依 XML 生成，你不用手動命名、不用手動搬檔。出完直接進 _export/<scene>/ 等你剪輯。

⑩ 路徑結構（V2 平層，沿用）

<trip>/
├── <場景>/                          ← 照片場景（ARW + Evotofu/）
├── _MOV/<scene>/<clip>.MOV           ← 影片母檔（永遠不切）
├── _STILL/<scene>/...               ← 智慧抽幀（看懂 + 評用途）
├── <trip>_FCP/Library.fcpbundle     ← FCP library（Leave in place，只記引用）
├── <trip>_LR/                       ← LR catalog（主管理）
├── _to_evoto/  _to_export/          ← 暫存（Evoto TIFF / LR 出 JPG）
└── _export/<scene>/                 ← 出片區（平層）
    ├── <photo>.jpg / <photo>-EVT.jpg  ← 照片出片
    ├── <clip>_KP<NN>_t<秒>.jpg        ← KP 單禎（V2.1）
    ├── <clip>_hl<NN>.mp4              ← HL 切片
    └── memoirs/<edited>.mp4           ← 你剪輯完成版
💡 為什麼平層：你要在 LR 內一個資料夾看完 photo + video。LR catalog 跟 FCP Library 各放獨立子資料夾（各自頻繁讀寫 + 備份，分開最乾淨）。

⑪ 編碼規格

出片 MP4（H.264，LR 預覽相容）

ffmpeg -i <src.MOV> -vf "scale=-2:1080,format=yuv420p" \
  -c:v libx264 -pix_fmt yuv420p -crf 20 -preset slow \
  -c:a aac -b:a 192k -movflags +faststart <dst.mp4>
🔥 必踩坑：別用 HEVC

LR Classic 預覽 HEVC（H.265）會顯示灰畫面（known bug）。10-bit 直編 QuickTime / Quick Look 也不解。出片走 H.264 + yuv420p 8-bit，檔案大 ~30% 但相容稅必付。

單禎 JPG

-frames:v 1 -q:v 2，抽 4K 原寬（之後可 re-frame / 印刷）。

⑫ Pick=-1 清理（釋出空間）

  • 你在 LR 把 MOV 標 Pick=-1 → Robert explicit 跑 cleanup_rejects.py 才處理
  • 安全機制：先搬 _TRASH/<scene>/ quarantine，7 天後才真刪（誤標可救回）
  • 刪 MOV 本體；不刪已抽出的 STILL / KP

⑬ 效率改善建議（給 James）

你的瓶頸在哪

V2.1 之後，判斷工作全集中在你身上：照片要檢查 + 出片，影片要撿片 + KP + HL + 剪輯。事情變多。下面 6 條照「省你最多動作」排序。

建議 1 ⭐ — KP 別截圖，改打 marker（最大省力）

手動截圖的 3 個隱形成本：畫質低（螢幕解析非 4K）、要自己命名、要自己搬檔。

改成：看到喜歡的畫面 → M 打 marker（要分級就 Option+M 打 KP_R）。Robert 從 XML 抽原片 4K 那一禎，畫質最高、命名自動、自動歸檔。你只按一個鍵。

建議 2 — 一次 Export XML 驅動全部

KP / HL / NG 全在 FCPX 一輪標完 → 只 export 一次 XML → Robert 一支腳本全跑（KP 抽圖 + HL 切片 + NG 記錄）。不要分「KP 給一次、HL 給一次」，減少你的交付動作。

建議 3 — 工具不要來回跳

影片端「人的判斷」全集中在 FCPX 一次做完，照片端全集中在 LR。在一個工具裡把該做的判斷一次做滿，再交給腳本，比邊看邊跳工具快很多。

建議 4 — Robert 多吃「分類勞動」，你只做「藝術判斷」

場景用途分類、NG 偵測、轉場偵測、主體分類 → 全部 VLM 先做完。你進 FCPX 時，每段已經有標籤告訴你「這是幹嘛的」，你只挑「哪段精彩、哪禎好看」。

建議 5 — 發佈搬檔自動化（沿用照片端）

_to_export → _export/<scene>/ 的搬移由 Robert 腳本一次做（你不用自己搬，除非你想自己搬）。影片切片 / KP 出圖直接落 _export/。

建議 6 — Trip 開工模板腳本

一個 new_trip.sh：自動建好資料夾結構（_MOV/_STILL/_export/...）+ 新建 FCP Library + 提示 keyword 綁定。你開工直接進撿片，不用每次手搭結構。

💡 整體心法：你做的事該只剩「不可外包的藝術判斷」 — 哪段精彩、哪禎好看、怎麼剪。所有「分類、命名、抽圖、切片、轉檔、搬檔、上雲」都是勞動，全歸 Robert 腳本。每多一個你手動做的勞動動作，就是一個可以拿掉的瓶頸。

⑭ 紅線 + checklist

🚨 千萬不要
  • ❌ 匯入勾「Copy to library」（影片重複，硬碟爆）
  • ❌ 選 Switch to HDR（撿片用不到）
  • ❌ 出片用 HEVC（LR 預覽灰畫面）
  • ❌ _MOV/ 搬完改名（破壞 FCP 重連）
  • ❌ LR catalog 跟 FCP Library 放同一子資料夾
  • ❌ NG 段切原檔（V2.1：只標不切）
✅ catalog 寫入安全（沿用照片端鐵則）
  • LR Cmd+Q → backup + integrity_check 'ok'
