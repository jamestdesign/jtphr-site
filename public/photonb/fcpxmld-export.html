撿片批次出圖 fcpxmld-export

📌 星等／KP／關鍵字的定義一律以 撿片關鍵字總表 為準（單一來源，本頁不重複定義）。

你在 FCPX 撿完片，Export 一個 .fcpxmld 交給我，一條指令全自動出圖：讀裡面的 keyword / star，自動切 HL 片段＋抽 KP 單禎，分場景輸出並寫好 LR 可讀色標。命名／分場景／轉檔／標註全自動，你不用手動做任何一步。

📄 本頁＝這支工具的單一現行說明。上游建 Library 見 旅遊影片匯入fcpx；FCPX 撿片操作＋完整工序見 影片剪輯知識庫。

做什麼

James FCPX 撿片（KP/HL）→Export .fcpxmld→fcpxmld-export→_preview_mov_HL/ ＋ _preview_mov_KP/
  • 讀 .fcpxmld 內的 KP keyword ＋ Star 評分 ＋ 場景關鍵字。
  • KP → 從原片抽原生解析度單禎 JPG，色標＋關鍵字＋來源時碼寫進 XMP，LR import 直接讀到。
  • HL（★4） → 切 1080p H.264 短片段，當「動態照片」觀賞。
  • 命名／分場景全由腳本依 XML 生成，你不用手動命名、不用手動搬檔。

怎麼用

# 撿完一天，把那天的 .fcpxmld 丟給我，一條指令：
fcpxmld-export "<trip>/_<trip>_FCPX/<MOV_day>.fcpxmld"

# 若這天是新規則（只打 KP、沒帶色碼），抽完圖 Robert 會接著跑辨識：
kp_autolabel.py "<trip>/_preview_mov_KP" --thumbs      # 出編號接觸表
kp_autolabel.py "<trip>/_preview_mov_KP" --apply decisions.json

腳本 tools/fcpxmld-export.py辨識 tools/kp_autolabel.py2026-07-07 起跨 trip 通用

💡 路徑自動推導（不再逐趟改碼）：從 argv 的 .fcpxmld 路徑自動抓 TRIP_ROOT 與素材夾 —— 依序試 ①同名 day 素材夾 ②剝掉 _主/_次 的同名夾 ③同 dayN 的 MOV_* ④_MOV ⑤退回 trip 本身。撿完一天丟該 day 的 .fcpxmld 即出圖。

🔒 輸出版面（鎖死・不要每次不一樣）

<trip>/_preview_mov_KP/<場景>/   ← KP 單禎 JPG
<trip>/_preview_mov_HL/<場景>/   ← HL 片段 mp4

<場景> = day 場景夾名。命名一眼看出是「mov 導出的預覽檔」。

⚠️ 素材若被 FCP 託管進 .fcpbundle，工具一律改抓 day 場景夾的原檔，輸出才會落對場景（不會套進 bundle 深層路徑）。

⭐2 工具標記 · 效果關鍵字建議

打 ★2 只是說「這段要加工」，加工成什麼由旁邊的關鍵字決定。建議先從最常用的四個開始用，其他等你想到再加。

關鍵字做什麼什麼時候用
拼貼丟進影片馬賽克（2×2／3×3 同時播）同一場景很多短片、單支都不夠強
慢動作 0.5x放慢一半（原片有 120/240fps 就用原生慢動作，沒有才補幀）水花、揮手、招牌轉場、food porn

定格抽一禎定住 1–2 秒（可加 Ken Burns 推移）強調某個瞬間、當段落收尾
循環來回循環（boomerang）短動作、招牌燈、旗子

💡 我的建議：先只用 拼貼／慢動作／快轉／縮時 四個 —— 這四個涵蓋八成情境，而且都能全自動做完不用你回頭確認。其餘等實際撿片時發現需要再開。關鍵字打在 FCPX 的 keyword 上，跟 ★2 同一段範圍，我讀 .fcpxmld 就抓得到。

兩種已實作的處理

AKP → 原生解析度單禎 ＋ 分類寫 XMP

讀 KP 的單禎時間點 → ffmpeg 抽原生解析度 JPG（-q:v 1）→ 色標寫進 XMP：
● R=紅色 臉/人像　● Y=黃色 背影　● G=綠色 風景　● P=紫色 物件
你 import LR 直接看到色標＋關鍵字＋來源時碼，不用再標一次。

🆕 2026-08-23 規則改了：你在 FCP 只要打 KP，不用再加 R/Y/G/P（那幾個快捷鍵留給你自己用）。
色標改成 Robert 在 export 之後看圖辨識補上——抽完圖會自動做一張編號接觸表，Robert 逐張判 R/Y/G/P、寫客觀描述，再寫回 JPG 並改檔名（_KP_t… → _KPG_t…）。
舊的 KP_R/Y/G/P 照吃，之前跑過的 trip 不會壞。

💡 小貼士：辨識完 檔名、關鍵字、色標、Description 四個地方會一起改。想自己覆蓋某一張，改 _autolabel/decisions.json 的 color 再跑一次 --apply 就好。

B★4 HL → 動態照片短片段

讀 ★4 的範圍（認定以 keyword + I/O 為準，Favorite 綠標只是視覺輔助）→ 切 H.264 1080p faststart 短片段。段邊界＝你 I/O 框的範圍。

色彩處理（自動判來源）

來源 colorSpace處理
Rec.2020 HLG（9-18-9，iPhone IMG_*.MOV）先 zscale + tonemap HLG→Rec.709 SDR，否則畫面會灰
Rec.709（1-1-1，手機 VID*.mp4）原樣不動

由每支素材的 <format> 自動判定，不用手動指定。

編碼規格

ffmpeg -i <src.MOV> -vf "scale=-2:1080,format=yuv420p" \
  -c:v libx264 -pix_fmt yuv420p -crf 20 -preset slow \
  -c:a aac -b:a 192k -movflags +faststart <dst.mp4>

🔥 必踩坑：別用 HEVC。LR Classic 預覽 HEVC（H.265）會顯示灰畫面（known bug），10-bit 直編也不解。出片一律走 H.264 + yuv420p 8-bit，檔案大 ~30% 但相容稅必付。
