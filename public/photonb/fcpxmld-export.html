撿片批次出圖 fcpxmld-export

你在 FCPX 撿完片，Export 一個 .fcpxmld 交給我，一條指令全自動出圖：讀裡面的 keyword / star，自動切 HL 片段＋抽 KP 單禎，分場景輸出並寫好 LR 可讀色標。命名／分場景／轉檔／標註全自動，你不用手動做任何一步。

📄 本頁＝這支工具的單一現行說明。上游建 Library 見 旅遊影片匯入fcpx；FCPX 撿片操作＋完整工序見 影片剪輯知識庫。

做什麼

James FCPX 撿片（KP/HL）→Export .fcpxmld→fcpxmld-export→_preview_mov_HL/ ＋ _preview_mov_KP/
  • 讀 .fcpxmld 內的 KP_R/Y/G/P keyword ＋ Star 評分 ＋ 場景關鍵字。
  • KP → 從原片抽原生解析度單禎 JPG，色標＋關鍵字＋來源時碼寫進 XMP，LR import 直接讀到。
  • HL（4★/5★） → 切 1080p H.264 短片段，當「動態照片」觀賞。
  • 命名／分場景全由腳本依 XML 生成，你不用手動命名、不用手動搬檔。

怎麼用

# 撿完一天，把那天的 .fcpxmld 丟給我，一條指令：
fcpxmld-export "<trip>/_<trip>_FCPX/<MOV_day>.fcpxmld"

腳本 tools/fcpxmld-export.py2026-07-07 起跨 trip 通用

💡 路徑自動推導（不再逐趟改碼）：從 argv 的 .fcpxmld 路徑自動抓 TRIP_ROOT 與素材夾 —— 依序試 ①同名 day 素材夾 ②剝掉 _主/_次 的同名夾 ③同 dayN 的 MOV_* ④_MOV ⑤退回 trip 本身。撿完一天丟該 day 的 .fcpxmld 即出圖。

🔒 輸出版面（鎖死・不要每次不一樣）

<trip>/_preview_mov_KP/<場景>/   ← KP 單禎 JPG
<trip>/_preview_mov_HL/<場景>/   ← HL 片段 mp4

<場景> = day 場景夾名。命名一眼看出是「mov 導出的預覽檔」。

⚠️ 素材若被 FCP 託管進 .fcpbundle，工具一律改抓 day 場景夾的原檔，輸出才會落對場景（不會套進 bundle 深層路徑）。

四種處理

AKP → 原生解析度單禎 ＋ 分類寫 XMP

讀 KP_R/Y/G/P 的單禎時間點 → ffmpeg 抽原生解析度 JPG（-q:v 1）→ 色標寫進 XMP：
● R=Red 臉　● Y=Yellow 背影　● G=Green 風景　● P=Purple 物件
你 import LR 直接看到色標＋關鍵字＋來源時碼，不用再標一次。

BHL（4★/5★）→ 動態照片短片段

讀 rating 4★/5★ 的範圍（認定以 keyword + I/O 為準，Favorite 綠標只是視覺輔助）→ 切 H.264 1080p faststart 短片段。段邊界＝你 I/O 框的範圍。Star3 = 只記不切。

CStar1（長篇發表・去 NG）→ 移除 Reject 拼成一支

你 I/O 框整段＋段內壞鏡頭按 Delete(Reject) → 工具挖掉壞段、把好段 concat 成一支完整長片，檔名標 Star1。屬「另外出片」的獨立長片。⚠️ concat 功能待補，規格已定。

DNG → 只記錄不切

短素材的 NG 段寫進 metadata 供劇本／剪輯跳過，原檔不動（只有 Star1 長篇會真的去 NG 拼接）。

色彩處理（自動判來源）

來源 colorSpace處理
Rec.2020 HLG（9-18-9，iPhone IMG_*.MOV）先 zscale + tonemap HLG→Rec.709 SDR，否則畫面會灰
Rec.709（1-1-1，手機 VID*.mp4）原樣不動

由每支素材的 <format> 自動判定，不用手動指定。

編碼規格

ffmpeg -i <src.MOV> -vf "scale=-2:1080,format=yuv420p" \
  -c:v libx264 -pix_fmt yuv420p -crf 20 -preset slow \
  -c:a aac -b:a 192k -movflags +faststart <dst.mp4>

🔥 必踩坑：別用 HEVC。LR Classic 預覽 HEVC（H.265）會顯示灰畫面（known bug），10-bit 直編也不解。出片一律走 H.264 + yuv420p 8-bit，檔案大 ~30% 但相容稅必付。
