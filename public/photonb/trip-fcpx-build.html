旅遊影片匯入fcpx trip-fcpx-build

📌 星等／KP／關鍵字的定義一律以 撿片關鍵字總表 為準（單一來源，本頁不重複定義）。

把整趟 MOV_<day> 一次匯進 Final Cut，自動分好 event（每天）＋場景關鍵字＋移動中/建築/飲食分類。James 開 Library 直接用關鍵字撿片，不用一夾一夾手動拖。影片 leave-in-place（不複製、不佔空間）。

📄 本頁＝這支工具的單一現行說明（功能日後在此統一更新）。撿完片的出圖端見 fcpxmld-export（§9）；完整影片工序見 影片剪輯知識庫。

做什麼

整趟 MOV_<day>/→trip-fcpx-build→FCPXML 1.10→FCP Library（.fcpbundle）→James 撿片
  • event = 每天（主／次各自拆成獨立 event，不混 —— 主＝我拍的主軸、次＝參考素材）。
  • 每個場景 = 一個 keyword collection：每個 clip 自動掛「場景名」當關鍵字 → 撿片時用關鍵字分類找片。
  • 分類關鍵字：每個 clip 另由場景名自動判 移動中建築飲食其他（混合場景給多類）→ James 在 FCPX 篩「移動中」撿片、觸發描述標籤。
  • 影片 leave-in-place：media-rep 指向原檔，MOV_ 當唯一原檔家，不複製、不佔空間。
  • 探測每支影片的解析度／fps／聲道（exiftool），自動建對應 <format>，時長對齊到最近的標準 fps。

怎麼用

# 產 FCPXML（可一次吃整趟 MOV_*/）
trip_fcpx_build.py "<trip>"/MOV_*/ --library "<….fcpbundle>" -o 匯入FCP.fcpxml

# → 再 FCP「File ▸ Import ▸ XML」或雙擊匯入（也可走 SpliceKit import_fcpxml）
# 匯入時 Leave-in-place 與場景關鍵字都已寫好，直接照 KB §8 綁 KP/HL 快捷鍵開撿

腳本 tools/trip_fcpx_build.pyFCPXML 1.10不給 --library 時預設 <trip>/_trip.fcpbundle

💡 跟 KB §8 的關係：這步取代「手動匯入 _MOV」那一動 —— 用工具產 fcpxml 一次匯完（已自動 Leave-in-place ＋ 場景關鍵字 ＋ 分類）。匯完就綁快捷鍵開撿。

event / 場景 結構（兩種都吃）

  • 平鋪場景＋_次（2026-07-01 新）：MOV_<day>/<NN_場景>/，帶 _次 尾綴的場景（第二台相機）自動拆成獨立的 <day>_次 event，主軸則是 <day>_主。
  • 舊 主/次 子夾（向後相容）：MOV_<day>/主(次)/<場景>/ 仍照吃，拆成 <day>_主 / <day>_次 兩個 event。
  • 同一場景在主/次夾內若重複，clip 併入同一 keyword collection。

由場景名關鍵字比對，一個 clip 可給多類，無匹配 = 其他：

⚠️「移動中」的精確定義（James 2026-07-07 拍板）

移動中 = 拍攝者本人在載具上移動（坐車／船／飛機拍窗外）。三條界線：

  • ① 邊走邊拍街景 = 街拍，不算移動中。
  • ② 站著不動、車／腳踏車從面前高速掠過 = 主體在動、我沒動（GPS 沒變），不算。
  • ③ 只有「人在移動載具上」才算。

故觸發字移除了泛用詞（移動／出發／途中／抵達／機場／高速…），並加 MOVE_EXCLUDE 強制排除：街拍・散步・步行・走拍・逛街・市集・車流・車陣・路邊・斑馬線・路口 —— 場景名即使帶交通字，命中排除詞就不判移動中。

❌ 試過並否決：畫面自動偵測「移動中」不可靠。camera_motion.py（相位相關算全域位移）德國實測分不開：手持走拍（科隆車站）畫面位移 mag61 ＞ 真在車上；飛機空拍雲海 mag0（無紋理追不到）。「坐車移動」vs「走路手持」訊號重疊甚至反轉，iPhone MOV 又只寫單一 GPS 定點無速度軌。結論：移動中只靠命名判斷 —— 歸檔時把在載具上的段落命名講清楚，灰色地帶（如「上山途中」巴士 vs 走路）列給 James 點一下，不自動猜。
