2.1 v4 LR Catalog Metadata Schema(2026-05-12 James 拍板) #

寫入端定版

Why: 實測 LR Classic 13+ 對 altTextAccessibility / extDescrAccessibility 兩個 IPTC 2017 新欄位,直接 SQL 寫入 column 不會在 UI 顯示(LR 同時檢查 AgMetadataSearchIndex 是否同步;走 LR-native UI 寫入或 XMP Read Metadata 才正常)。為了避免 XMP round-trip,改用 SQL 一定吃的欄位重新配置中繼資料分工。

欄位分工(VLM CSV → LR catalog)

LR UISQL 表 / 欄位內容主用者
關鍵字 AgLibraryKeyword.name + AgLibraryKeywordImage objective_description 用 + 切分,每段一個 keyword Robert(VLM 寫入)
註解 AgLibraryIPTC.caption 機器 tag + 雙方對話日誌 雙方共用
替代文字 AgLibraryIPTC.altTextAccessibility 暫不用 LR SQL 直寫不顯示 —
延伸描述 AgLibraryIPTC.extDescrAccessibility 暫不用 LR SQL 直寫不顯示 —
評等 / 旗標 / 色標 Adobe_images.rating / pick / colorLabels 標準 v3 評分 Robert

註解格式(共用對話日誌,| 數標輪次)

turn 0 (Robert 初寫):
[表情:big_laughing] [動作:hugging_mascot_full_joy] [主體:human_face_clear] [conf:0.92]

turn 1 (James 加註,單 |):
[表情:...] [動作:...] [主體:...] [conf:0.92] | 大笑表情完美,主體判斷正確 ★★★★★

turn 2 (Robert 回應,雙 ||):
[表情:...] ... ★★★★★ || 已加入 SKILL hugging_mascot 權重 ✓

turn 3 (James 再加,三 |||):
... ✓ ||| 確認 SKILL update
  • 數 | 個數判斷輪次,新內容永遠 append 在最末
  • 永不覆蓋既有內容 — UPDATE 前先讀 caption,在原文後 append
  • 缺機器 tag 的照片(312/1280 v2 schema)→ 註解寫 [需補tag] 標記,Smart Collection 可篩出待補

關鍵字寫入規則(符合 LR 規範)

  • 用 + 切 objective_description
  • 每段 strip() 前後空白
  • 跳過空字串、跳過 1 字元雜訊、跳過純標點
  • 不重複既有 keyword(查 AgLibraryKeyword.lc_name 確認)
  • 既有 scene / 人物 tag(1112_N, 女A, 男A 等)保留不動
  • 範例:熊本城石碑+石牆+樹+施工鷹架+陰天 → 5 個獨立 keyword

Smart Collection 篩選範例

  • 關鍵字 包含 "施工鷹架" → 所有有施工背景的照片
  • 註解 包含 "[需複查]" → Robert 標記要 James audit 的
  • 註解 包含 "[需補tag]" → 缺 v3 tag 的 312 張
  • 註解 包含 " || " → 已經有對話往返的照片

為什麼這樣分?

  1. 關鍵字 = scene 描繪的天然容器,每段獨立 = LR keyword filter / Smart Collection 都能用
  2. 註解 = 唯一同時滿足「SQL 直寫即顯示」+「文字長」+「Smart Collection 文字搜尋」的欄位 → 適合放機器 tag + 對話日誌
  3. 延伸描述 / 替代文字 = LR Classic 13+ 加的新欄位,需要走 XMP 或 LR-UI 寫入才會顯示,SQL 直寫只進 column 不進 index → 避開
  4. 未來如要救活替代文字 / 延伸描述,得寫 XMP sidecar + LR 觸發「中繼資料 → 從檔案讀取」

已驗證的 SQL 寫入 pattern

# 清除舊註解 + 寫新內容(僅限 master scope 1280 baseName)
cur.execute("""
  UPDATE AgLibraryIPTC SET caption=? WHERE image=?
""", (new_caption, img_id))

# 新增 keyword(若 lc_name 不存在則建,再 link 到照片)
cur.execute("INSERT OR IGNORE INTO AgLibraryKeyword (id_global, name, lc_name, ...) VALUES (?, ?, ?, ...)")
cur.execute("INSERT OR IGNORE INTO AgLibraryKeywordImage (image, tag) VALUES (?, ?)")

前置安全: LR 必須 Cmd+Q;backup → /tmp 副本 → SQL → integrity_check → cp 回 SSD(遵守 feedback_lr_catalog_sql_safety.md 鐵則)。

3. SKILL 規則庫版本 #

Source of truth: ~/Desktop/Claude-Workspace/photo-grade/SKILL_robert_portrait_rating.md

3.1 四軸 Label 對應(2026-05-08 重要)

Label 不是視覺分類,是評分軸切換 / 工作流程分類:

Label主體評分主軸後續工作流
Red 人臉清楚可辨(正面/3-4 側/部分遮蔽) 眼神 + 表情 + 笑容(三道把關) 會跑 Evoto AI 人臉精修
Yellow 人但臉不可辨(背影/剪影/太遠) 故事情節 + 氛圍 + 構圖 不跑 Evoto,LR 純參數
Green 風光 / 室內空間 / 無人 構圖切割 + 場景唯一 + 動態事件 LR 直接出片(無人臉)
Purple 食物 / 藝術品 / 商品 創作物視覺 LR 直接出片

3.2 Red 軸三道把關

三道任一掛了 → 直接 2★:

  1. 表情 — 自然 vs 僵硬
  2. 笑容 — 起來 vs 收攏(笑累了) vs 太用力
  3. 眼神 — 有神 vs 疲憊 vs 失焦 vs 上吊

5★ 鐵三角:(a) 看鏡頭 + (b) 燦爛真笑 + (c) 構圖到位 + (d) 氛圍加分 → 缺一頂多 4★。

4★ 門檻:4 軸有 3 個到位 + 表情不僵。

v2 慷慨原則:同場景 burst 都笑+看鏡頭時可以都 4★,不必強制「擇優扣分」。

3.3 Green 軸完整規則 v2(30 條精選)

A. 評分基本面

  • 場景唯一+合焦+工整 → 3★+P (default 保留層)
  • 沒明顯瑕疵的雷同 → 3★ default (v2 校正,不再降 2★)
  • 1★ 真正門檻嚴格:失焦/HDR反曝光/主體消失/構圖凌亂無法後製
  • 構圖鬆 ≠ 1★ (最多 2★);平光無戲劇 ≠ 1★ (最多 3★)

B. 4★ 觸發點

  • 完美對稱構圖
  • 風光課本式三段式 (天-中-地)
  • 微裁切後即達標
  • 慢快門技法成功 (動靜分離)
  • 同主題擇優代表

C. 唯一性 6 維度判斷(v2 重點)

判定兩張是否「真雷同」: 焦段 / 拍攝角度 / 視角位置 / 前景元素 / 構圖意圖 / 動態瞬間。任一維度顯著不同 = 獨立視覺單位 = 可獨立 P。必須多維度都一致才算真雷同。

真雷同擇優依據優先順序:① 畫面乾淨度(無玻璃反光/雨滴/路人)⭐ 首要 → ② 構圖切割品質 → ③ 動態瞬間捕捉

3.4 Pick (P) 決策公式

# Red / Yellow 軸
P = (rating >= 4)
   OR (rating == 3 AND 場景內 4 軸 profile 唯一無重複)

# Green 軸特殊(更寬鬆)
P_green = (rating >= 4)
   OR (rating == 3 AND 場景唯一 OR 動態事件 OR 不同取景單位)

3.5 同場景情境 4 軸

軸類別
動作類型靜止站 / 行進中 / 互動觸物 / 坐 / 手勢
視線方向看鏡頭 / 看物件 / 凝視遠方 / 閉眼低頭
環境互動主動互動 / 被動經過 / 純擺拍靜態
構圖意圖正中對稱 / 動態流動 / 紀念紀錄

判定:≥2 軸類別不同 → 兩張都 P(情境並列);4 軸全同只差微表情 → 走擇優 N+(N-1)。

4. VLM 防幻覺紅線(2026-05-10 calibration) #

背景: 2026-05-10 Sonnet agent 跑 1280 張 backlog,1057 場景出現 70-80% 幻覺。User 花 90 分鐘逐張校對(等於從零做一次)。後制定 6 條 hard constraint,違反即整批退回。

幻覺實證案例

filename實際畫面Sonnet 錯誤輸出
IMG_5361女子坐單人沙發正面笑容「大廳熊本熊布偶陳設」+ Label=Purple
IMG_5364空沙發無人「搞怪姿勢稀有」+ Label=Red
IMG_5365男人+熊本熊合照「木雕陶偶藝術品」+ Label=Purple
IMG_5356酒瓶+杯子(主體=酒)Label=Green

6 條紅線

紅線 1

禁止編造畫面描述

每張先輸出 objective_description 欄位(≤30 字)— 客觀描述「畫面實際看到」,不能含揣測 / 聯想 / 場景假設。

規則:先描述 → 再 label → 再 rating。順序顛倒 = 幻覺溫床。

紅線 2

Label 由主體唯一決定

沒有「綜合判斷」、沒有「氛圍考量」、沒有「除非...」例外:

  • 人臉清楚可辨 → Red(背景再多藝術品都不變)
  • 商品/酒/食物為主體 → Purple(旁邊有杯子也不變)
  • 人但臉完全看不到 → Yellow
  • 空間/風景/室內無人 → Green
紅線 3

同場景同主體 → 同 label

三張酒瓶不能拆 Purple+Purple+Green;三張自拍不能拆 Red+Red+Purple。Label 由主體決定,Pick 由場景代表權決定。

紅線 4

confidence < 0.7 → 一律 flag human review

不可以「猜不準就隨便給分」。confidence < 0.7 → JSON 必須有 "needs_human_review": true,不寫 catalog SQL(先 flag 給 user)。

紅線 5

縮圖 ≥1024px / Opus only / 拆兩階段

  • 縮圖不可低於 1024px 長邊(之前 512px 是幻覺源頭)
  • Production 跑 backlog Opus 4.7 only;Sonnet 只能用於 dev/sample audit
  • Label-only pass(含 objective_description)→ user audit 10 張 → OK 才跑 Rating pass。不准合併
紅線 6

JSON 欄位必填

{
  "filename": "IMG_5361.JPG",
  "objective_description": "女子坐單人沙發 正面笑容 黃調燈光",
  "subject_type": "human_face_clear" | "human_no_face" | "product" | "space_no_human",
  "label": "Red" | "Yellow" | "Green" | "Purple",
  "rating": 1-5,
  "rating_range": [N-1, N+1],
  "pick": true | false,
  "scene_id": "<HHMM 場景名>",
  "scene_role": "unique" | "representative" | "alternate" | "redundant",
  "confidence": 0.0-1.0,
  "needs_human_review": false,
  "notes": "≤15 字中文"
}

subject_type 必須跟 label 對齊,Audit 工具自動檢查不一致 → 整 batch 退回。

① Orientation 反向(2026-05-10 修補)

7. LR AutoTone SQL 觸發機制 #

原理: AutoTone 是 LR 的「自動」按鈕功能,根據照片內容算出 Exposure/Contrast/Highlights/Shadows/Whites/Blacks 6 個 tone 軸最佳值。但用 SQL 直接設 crs:AutoTone="true" 而留著現成 Exposure2012 等值,LR 不會重算。

正確步驟

  1. 關閉 LR(no -wal/-shm/-lock files)
  2. 在 Adobe_imageDevelopSettings.text(Lua 序列化字串)裡:
    • 移除:Exposure2012, Contrast2012, Highlights2012, Shadows2012, Whites2012, Blacks2012, ParametricShadows, ParametricHighlights, ParametricLights, ParametricDarks, AutoToneDigest, AutoToneDigestNoSat
    • 加入:AutoTone = true, 在最後 } 前
    • 重算 MD5 digest 寫回 digest 欄位
  3. INSERT 新的 history step: 
    INSERT INTO Adobe_libraryImageDevelopHistoryStep (
  id_global, image, dateCreated, name, valueString, hasDevelopAdjustments
) VALUES (uuid, image_id, now_cocoa, '從中繼資料', 'calculate', 'calculate');
    valueString='calculate' 是關鍵 — LR 看到才會重新讀 develop text。

已驗證

2026-05-08 對門司港 627 張照片成功 — LR 重開後每張顯示不同的 Exposure/Contrast(自動算的值),色調仍是 Style A/B/C/D 的設定。

LR 不認的格式

  • AutoTone = "true"(字串)→ LR 視為 false
  • AutoTone = 1(數字)→ 失敗
  • AutoTone = true(Lua boolean)→ 成功

三段式工作流哲學(2026-05-09 暫存設計)

1️⃣ AutoTone(per-photo 自動)
    └─ Exposure / Contrast / Highlights / Shadows / Whites / Blacks

2️⃣ Adaptive Preset(per-photo AI mask,可選)
    └─ Red 套「自適應:主體」→ 提亮膚色+加銳臉部
    └─ Green 風光含天空套「自適應:天空」
    └─ Yellow 視構圖選

3️⃣ 氛圍 Preset(全組統一)
    └─ HSL / Color Grading / Tone Curve / Detail / Effects / Calibration

哲學:旅遊現場 = 變數(每張光源不同)→ AutoTone per-photo 處理曝光;氛圍感 = 常數(全組統一風格)→ Preset 處理風格層。「讓機器處理變數,人類處理常數風格」的智慧分工。
