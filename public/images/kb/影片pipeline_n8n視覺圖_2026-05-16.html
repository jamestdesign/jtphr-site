💡 小貼士編碼規格(2026-05-17 v3,LR 預覽相容版): 
ffmpeg -i <src> -vf "scale=-2:1080,format=yuv420p" \
  -c:v libx264 -pix_fmt yuv420p \
  -crf 20 -preset slow \
  -c:a aac -b:a 192k \
  -movflags +faststart <dst>.mp4
  • 1080p(scale=-2:1080):雲端 / 手機觀看標準解析度,4K 上傳慢且大多手機螢幕看不出差別
  • H.264 (AVC)(2026-05-17 v3 改用):**LR Classic 預覽相容**(HEVC 在 LR 顯示灰畫面)— 檔案比 H.265 大 ~30% 但 LR 一定能播
  • 8-bit(format=yuv420p):強制 8-bit 色深 — 原 MOV 是 10-bit 但所有預覽工具(QuickTime / LR / Quick Look)都吃 8-bit
  • CRF 20:H.264 的 CRF 20 約等於 H.265 CRF 22(視覺接近無損)
  • preset slow:編碼較慢但壓縮率好(壓出小檔)— 出片不在乎時間
  • +faststart:MP4 metadata 移到檔頭,網頁 / 雲端串流可**邊載邊播**(不用全載完才能看)
  • AAC 192k:立體聲清晰、通用音訊 codec,所有平台都認
  • NG 不切(2026-05-17 廢掉),原檔母片永遠保留在 _MOV/
  • HL ⊆ KP:HL 出片同時自動納入 Step 11 劇本 KP 池,同段不重複切
  • 輸出位置平層(2026-05-17 v2):_export/<scene>/<clip>.mp4 直接放在場景資料夾下,**不用 出片/ 子層
  • 同時 INSERT LR catalog:出片完直接寫進 catalog,James 在 LR 看得到管理(不用 sync folder)
  • 📝 為什麼不用 H.265(踩坑紀錄):2026-05-17 first try H.265 10-bit → QuickTime 不解 video。改 8-bit + hvc1 tag → QuickTime 通了,但 LR 還是灰畫面。**LR Classic HEVC bug 已知,直接 H.264**。檔案大 ~30% 是必要的相容稅。
